# Типові помилки Telegram-бота

## `BOT_TOKEN is not set`

**Симптом:** бот завершує роботу одразу після запуску з повідомленням про відсутній `BOT_TOKEN`.

**Причина:** у корені проєкту немає файлу `.env` або в ньому немає змінної `BOT_TOKEN`.

**Рішення:** створіть `.env` на основі шаблону й додайте токен від `@BotFather`:

```bash
cp .env.example .env
```

```env
BOT_TOKEN=ваш_токен
```

## `TelegramConflictError`

**Симптом:** у логах з’являється повідомлення `Conflict: terminated by other getUpdates request`.

**Причина:** один токен використовується двома запущеними екземплярами бота — наприклад, у Docker і в іншому терміналі.

**Рішення:** зупиніть зайвий процес через `Ctrl+C` або зайвий контейнер командою `docker stop <container_id>`. Має працювати лише один бот із цим токеном.

## Зміни коду не підхоплюються

**Симптом:** після збереження `app/main.py` бот продовжує працювати зі старою версією коду.

**Причина:** контейнер не запущений або hot-reload не бачить змін файлів.

**Рішення:** перевірте статус і логи:

```bash
docker compose ps
docker compose logs -f bot
```

У логах `watchfiles` має з’явитися повідомлення `change detected`. У Docker Compose увімкнено polling-режим, щоб hot-reload коректно працював з bind mount на macOS.

## `.vscode/` відображається як `untracked`

**Симптом:** команда `git status` показує папку `.vscode/` у списку `Untracked files`.

**Причина:** Cursor або VS Code створив локальні налаштування редактора для цього проєкту. Git не відстежує їх, бо папку не додано до коміту й не зазначено в `.gitignore`.

**Рішення:** якщо налаштування не потрібні, папку можна безпечно видалити. Якщо вона має залишатися локальною, додайте до `.gitignore` рядок:

```gitignore
.vscode/
```

Не додавайте `.vscode/` до коміту, якщо вона не містить спільних для команди налаштувань.
