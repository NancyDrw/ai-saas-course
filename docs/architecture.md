# Архітектура Intima

## Назва та мета продукту

**Intima** — Telegram-бот для дорослих користувачів, який допомагає дбайливо говорити про близькість і стосунки. Поточна версія є мінімальним прототипом: вона вітає користувача, показує меню та коротко описує заплановані розділи.

## Frontend

Інтерфейсом продукту є Telegram. Через нього користувач:

- надсилає команди `/start`, `/help` і `/menu`;
- бачить повідомлення бота;
- натискає кнопки меню: «AI-сексолог», «Профіль пари», «Сумісність» та інші.

Окремого веб- або мобільного інтерфейсу в поточній версії немає.

## Backend

Backend — Python-застосунок на `aiogram`, розташований у [app/main.py](../app/main.py). Він:

- отримує повідомлення користувачів;
- знаходить обробник для відповідної команди або кнопки;
- формує текст відповіді;
- надсилає відповідь і клавіатуру назад у Telegram;
- записує основні події до логів.

Наразі реалізовано обробники `/start`, `/help`, `/menu` і вибору пунктів меню. Для пунктів меню бот повідомляє, що інтерактивні сценарії ще в розробці.

## Database

База даних поки не підключена. Поточний бот не зберігає профілі, відповіді користувачів, історію діалогів чи результати перевірок.

У майбутньому база даних може зберігати:

- профілі користувачів і пар;
- відповіді на опитування та налаштування;
- записи Intimacy Check-in;
- історію вправ, карток і рекомендацій;
- агреговані дані для Insights.

## API

Застосунок взаємодіє з Telegram через **Telegram Bot API**. Бібліотека `aiogram` отримує оновлення від Telegram і викликає Python-обробники. Відповіді бота також надсилаються до Telegram через це API.

## Приклад роботи: команда `/start`

1. Користувач надсилає `/start` у чаті з ботом.
2. Telegram передає повідомлення застосунку через Telegram Bot API.
3. `aiogram` розпізнає команду та запускає обробник `cmd_start` у `app/main.py`.
4. Backend формує привітальне повідомлення й клавіатуру з пунктами меню.
5. Застосунок надсилає відповідь через Telegram Bot API.
6. Користувач бачить привітання та може обрати розділ у Telegram.

Для цієї дії база даних не потрібна, оскільки бот не зберігає і не читає дані користувача.

## Docker

Docker не є частиною frontend, backend або бази даних. Він створює однакове середовище для запуску Python-застосунку. Конфігурація міститься у [Dockerfile](../Dockerfile) та [docker-compose.yml](../docker-compose.yml).

## Майбутній розвиток

- **Database:** підключити базу даних для профілів, відповідей і динаміки check-in.
- **AI-модель:** backend збиратиме потрібний контекст, надсилатиме запит до AI через API та повертатиме користувачу пояснення, вправи або рекомендації.
- **Функції:** реалізувати повноцінні сценарії для профілю пари, сумісності, карток для розмов, вправ і Insights.
- **Інтерфейс:** за потреби додати веб-інтерфейс, який працюватиме з backend через окремий API.

Ці можливості є запланованими: у поточному прототипі вони ще не реалізовані.

## Розбір функцій реальних застосунків

Нижче — навчальний розбір. Він пояснює відповідальність блоків без припущень про внутрішній код, сервери чи конкретні технології сторонніх сервісів.

### 1. Банківський застосунок: перегляд балансу

- **Що робить користувач:** відкриває застосунок і переходить на екран рахунків.
- **Frontend:** показує рахунки, баланс і кнопку оновлення.
- **API:** передає запит застосунку до серверної частини банку та повертає дані.
- **Backend:** перевіряє, що користувач авторизований і має доступ до рахунків, після чого готує відповідь.
- **Database:** зберігає дані рахунків та операцій, з яких обчислюється або отримується баланс.
- **Результат:** користувач бачить актуальний баланс своїх рахунків.

### 2. Trello: створення задачі на дошці

- **Що робить користувач:** вводить назву задачі та натискає кнопку створення картки.
- **Frontend:** показує дошку, форму введення та нову картку в потрібній колонці.
- **API:** надсилає дані нової картки з клієнтського інтерфейсу до сервера.
- **Backend:** перевіряє доступ користувача до дошки, перевіряє введені дані та створює задачу.
- **Database:** зберігає картку, її назву, колонку, автора та інші параметри.
- **Результат:** нова задача з’являється на дошці й доступна іншим учасникам, які мають доступ.

### 3. Telegram: надсилання повідомлення

- **Що робить користувач:** вводить текст у чаті та натискає «Надіслати».
- **Frontend:** показує поле введення, кнопку надсилання і повідомлення в чаті.
- **API:** передає повідомлення між клієнтським застосунком Telegram і сервісами Telegram.
- **Backend:** приймає повідомлення, перевіряє можливість його доставлення та організовує доставку адресату.
- **Database:** зберігає дані повідомлення та історію чату відповідно до налаштувань сервісу.
- **Результат:** адресат отримує повідомлення у своєму Telegram-клієнті.

### 4. Spotify: відтворення треку

- **Що робить користувач:** обирає трек і натискає кнопку відтворення.
- **Frontend:** показує обкладинку, назву треку, прогрес і керування плеєром.
- **API:** передає запит на відтворення та отримує дані, потрібні для доступу до аудіо.
- **Backend:** перевіряє обліковий запис і права на відтворення, після чого готує доступ до треку.
- **Database:** зберігає каталог музики, дані профілю та плейлисти; також може зберігати історію прослуховування.
- **Результат:** користувач чує вибраний трек і бачить стан його відтворення.

## Перевірка документа

- Опис відповідає коду в `app/main.py`: у боті є команди `/start`, `/help`, `/menu` і кнопки меню.
- Реалізовані частини відокремлено від запланованих у розділах **Database** та **Майбутній розвиток**.
- Ролі блоків визначені явно: Telegram показує інтерфейс, Python/aiogram обробляє повідомлення, а база даних у поточній версії відсутня.
- Документ не містить токенів, паролів, значень змінних середовища або вмісту `.env`.
