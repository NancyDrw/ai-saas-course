# Безпека секретів

## Що таке секрет

Секрет — це конфіденційне значення, яке надає доступ до системи, даних або зовнішнього сервісу. Якщо його побачить стороння людина, вона може видати себе за бота, отримати доступ до бази даних або змінити дані.

Секрети не можна додавати до коду, Git-історії, README, скріншотів, повідомлень у месенджерах або логів.

## Секрети цього проєкту

- `BOT_TOKEN` — токен Telegram-бота. Він дає змогу керувати ботом через Telegram Bot API.
- `DATABASE_URL` — рядок підключення до Neon PostgreSQL. Він містить адресу бази, назву бази, логін і пароль.

Назви змінних не є секретами. Секретними є їхні реальні значення.

## `.env` і `.env.example`

`.env` — локальний файл із реальними секретами конкретного середовища. Він має бути в `.gitignore` і ніколи не комітується.

```env
BOT_TOKEN=real_token_is_stored_only_locally
DATABASE_URL=real_connection_string_is_stored_only_locally
```

`.env.example` — безпечний шаблон, який комітується. Він показує, які змінні потрібні для запуску, але містить лише заглушки.

```env
BOT_TOKEN=your_bot_token_here
DATABASE_URL=your_database_url_here
```

Щоб налаштувати проєкт локально, скопіюйте шаблон командою `cp .env.example .env` і вставте власні реальні значення тільки у `.env`.

## Дії при витоку секрету

Якщо секрет опинився в GitHub, логах, скріншоті або повідомленні, вважайте його скомпрометованим навіть після видалення з файла.

1. Негайно перевипустіть секрет: створіть новий токен у BotFather або змініть пароль/рядок підключення в Neon.
2. Оновіть локальний `.env` новим значенням.
3. Видаліть старе значення з коду, логів, документації та публічних повідомлень.
4. Якщо секрет був закомічений, приберіть його також із Git-історії за узгодженим процесом команди.
5. Перевірте доступ до бота й бази даних із новими значеннями та повідомте команду про інцидент.

Видалення секрету з останнього коміту без його перевипуску не робить секрет безпечним.
